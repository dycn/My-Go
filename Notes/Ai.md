#### Ai通识
- 神经元网络模型
    - 输入层 入口，接收数据
    - 隐藏层 输入层结果加权求和 信息处理和学习 （AI难点就是找到合适的权重）
    - 输出层 出口，产生结果
    - 例如 手写数字识别
        - 输入层 图片每个像素点的灰度值(1是亮 0是灭)
        - 判断像素点的形状
    - 解决合适权重问题的方法 反向传播
        - 前向传播 数据逐层加工，直到产生结果
        - 计算误差 计算产出结果和正确结果的误差
        - 反向追责 倒推每一层的每个连接对误差的贡献 (其中误差计算有损失函数相关知识)
        - 调整权重 根据每个连接的误差贡献比例，调整权重参数 (追责和调整权重有梯度下降算法)
- 数学运算是如何理解人类语言的？ 大语言模型
    - 词向量 把词转为多维空间向量
        - 首先将人类自然语言拆分为一个个片段，称为Token(词)
        - 每个Token经过模型计算转为一个浮点数数组，作为向量坐标
        - 使词向量在多维空间中的不同方向表达不同的含义
            - 女人 - 男人的向量差 跟 阿姨 - 叔叔  王后 - 国王 向量差很类似
            - 向量差 即方向，逐渐有了含义 某种意义上 妈妈 = 爸爸 + 女人 - 男人 具有推理能力
    - transformer模型
        - 其注意力机制使模型更高效的根据上下文信息处理token，理解token含义
        - Attention 感知层
        - MLP 多层感知积
        - 不断重复Attention和MLP
        - softMax 根据模型计算出的向量结果 得出下一个Token的概率分布，然后基于概率的随机采样方式挑选一个作为结果。
    - 大语言模型
        - transformer本来是作为翻译使用的，但当模型规模和训练数据量增突破某个临界点，模型像是可以理解人类语言，还能分析、推理，这种现象称为涌现。这种超大规模的语言模型称为大语言模型
    - 上下文如果太大，模型算不出来 所以现在上下文都有限制(128k)，会有记忆丢失现象

#### 大模型
- gpt
    - t transformer 深度学习的一种神经网络结构
    - p pre-trained 预训练
    - g generative 生成式，根据上文预测紧跟着的下一个Token，从而形成连续的文本输出
    - gpt是openAI公司研发的一个基于transformer架构的大语言模型(LLM)
- 大模型应用
    - 对话机器人 可以与用户聊天、答疑，具有记忆的大模型应用。例如chatGPT、通义千问
    - AI大模型基于大模型推理、分析、生成能力，传统编程则更擅长精确计算、控制，大模型应用结合了两者的优势
    - 应用结构
        - 通常用传统web应用作为入口，再由传统应用调用大模型服务提供的基于HTTP协议的API接口，实现用户与大模型的交互


#### 一些概念
- LLM 大语言模型 类似大脑
- RAG 检索增强生成 外挂资料库
    - 解决了LLM两个核心痛点
        - 减少胡说八道 让LLM去指定资料库翻书
        - 接入私有知识 让AI变成只有你服务的私人专家
- MCP model context protocol 万能转接头
    - 远古时代各个AI工具各有一套标准，MCP出现后统一了标准
    - 统一标准，定义了模型和工具间的交互规范
    - 即插即用 任何符合MCP标准的工具都能像U盘一样使用
    - 生态繁荣 催生了mcp.so、mcpmarket等MCP服务提供商
- Agent 智能体 AI系统的“总指挥”
    - 核心能力：接收用户需求后，能自主理解意图、拆解复杂任务、规划执行步骤、决策调用哪些资源（知识/工具），并完成整个任务的闭环反馈
    - 工作模式
        - 接收目标 例如"帮我调研A公司最近动态，整理成报告"
        - 自主规划 分析任务步骤(搜索新闻->查财报->总结->输出)
        - 调用工具 通过MCP调用网页搜索、数据库查询等工具
        - 整合交付 生成完整报告并交付
    - 四种演进阶段
      | 阶段 | 技术方案 | 典型场景 | 优缺点 |
      | --- | --- | ---- | --- |
      | 问答智能体 | 知识库+RAG+LLM | FAQ、知识查询 | 简单快速，但无法处理复杂问题 |
      | SOP智能体 | 预定义流程编排 | AI搜索、OA审批 | 标准化高效，但灵活性差 |
      | 通用智能体 | 反思+规划+执行 | 开放问题求解、个人助理 | 灵活强大，但成本高、不稳定 |
      | 协同智能体 | 专业+多角色协同 | 自主软件开发、智能解说 | 专业鲁棒，但系统复杂 |
- Skills 专业化能力模块
    - 是Agent的能力扩展包，让通用Agent具备特定领域的专业能力
    - 特点
        - 模块化设计 每个Skill专注于特定功能
        - 可组合性 多个Skill组合解决复杂问题
        - 可重复性 同一Skill可以在不同Agent中使用
    - 典型实例
        - 数据分析Skill 处理excel、生成图表
        - 图像处理Skill 识别图片内容、生成图像
        - 代码生成Skill 根据特定需求生成特定语言代码
        - 文档处理Skill 解析PDF、Word文档
- Agent集群 AI团队协作
    - 单个Agent虽然强大，但在处理超复杂任务时仍有局限。Agent集群通过多智能体协同，实现了更高级的智能
    - 优势
        - 专业化分工
        - 并行处理
        - 相互验证
        - 弹性扩展
    - 典型应用
        - 自主软件开发 需求分析Agent + 设计Agent + 编码Agent + 测试Agent
        - 智能客服系统 意图识别Agent + 知识查询Agent + 情感分析Agent + 响应生成Agent
        - 金融分析平台 数据收集Agent + 风险评估Agent + 投资建议Agent + 报告生成Agent

- ReAct Agent
    - 核心原理
        - 名字来源两部分
            - Reason 思考。
                - LLM 会生成思维链（Chain-of-Thought），这是一种详细的推理过程，包括它对问题的理解、如何拆解问题、以及接下来打算做什么
            - Act 行动
                - LLM 会根据它的思考，调用外部工具或执行特定操作。这些工具可以是搜索、计算运算、代码解释、API接口(查询天气、发送邮件等)
        - 工作流程
            1. 接收任务 给LLM一个任务
            2. 思考
            3. 行动 根据思考结果，选择一个合适的工具执行操作(例如调用搜索引擎搜索)
            4. 观察 接收工具执行后的结果
            5. 循环 根据观察到的结果重新回到思考步骤
            6. 输出答案
    - 强大的原因
        - 提高准确性 通过调用工具获取最新最准确信息，避免不真实信息
        - 处理复杂任务 将大任务分解为小步骤
        - 可解释性 LLM生成的思考链使得它的决策过程更加透明，可以看到它时如何思考和解决问题的，有助于调试和理解
        - 适应动态环境 LLM可以根据外部工具的反馈动态调整其行为和策略
- MoE编排 Mixture of Experts Orchestration
    - 一种让LLM更高效、灵活处理各种任务的策略。
    - 核心思想
        - 专家混合
        - 多个小型专家模型，针对不同任务和数据类型，训练一些相对较小的专门化的模型
        - 路由网络，小型的神经网络，任务是根据输入的任务或数据，决定将任务路由给哪个或者哪几个专家来处理
    - 工作原理
        1. 路由决策。判断任务性质，比如是关于历史知识、编程代码还是创意写作
        2. 专家激活 激活一个或几个专家模型
        3. 专家处理
        4. 结果整合
    - 优点
        - 提高效率和速度
        - 处理多样化任务
        - 更好性能
        - 可扩展性
